Parking Lot System

The most classic LLD interview question — worked end-to-end from requirements to a runnable design, with the patterns from earlier pages applied for real.

🚗 Practice Problem ⏱ ~25 min read 🎯 Combines OOP + SOLID + Patterns
💡 Why start here

Parking Lot shows up constantly because it naturally forces every skill from the earlier pages at once: multiple entity types with an inheritance-ish hierarchy, a Strategy for pricing, a Singleton for the lot itself, and composition all the way down (Lot → Floors → Spots). If you can design this cleanly, you can adapt the same shape to most other LLD problems.

1Problem Statement

Design a parking lot system that supports:

  • Multiple floors, each with a number of parking spots of different sizes (motorcycle, compact, large).
  • Multiple vehicle types (motorcycle, car, truck) that can only park in compatible spot sizes.
  • Issuing a ticket when a vehicle enters, and calculating a fee based on duration when it exits.
  • Telling a driver "lot full" when no compatible spot is available.

2Clarifying Requirements

Always state these out loud before designing — it shows the interviewer you think about scope before jumping to code.

FunctionalNon-functional
Park a vehicle in the nearest compatible free spotSpot lookup should be reasonably fast (not a full scan for large lots)
Unpark a vehicle and calculate the feeThread-safety if multiple entry gates run concurrently
Support multiple vehicle and spot types with compatibility rulesEasy to add a new vehicle type or pricing scheme later (OCP)
Track how many spots are free, per floorThe parking lot itself is a single, shared, global resource

3Identifying Core Entities

Pull the nouns straight out of the problem statement — each becomes a class:

EntityResponsibility
VehicleHolds license plate + vehicle type
ParkingSpotHolds spot type, tracks whether it's occupied
ParkingFloorOwns a list of spots, finds an available compatible one
ParkingLotOwns all floors; the single entry point for park/unpark
TicketRecords vehicle, assigned spot, entry/exit time
PricingStrategyCalculates the fee for a completed ticket

4Design Decisions & Patterns Used

DecisionPatternWhy
Exactly one ParkingLot instance for the whole buildingSingletonThere's only ever one physical lot — no reason for two independent instances to exist in memory
Fee calculation is pluggable (hourly today, could be flat-rate or weekday/weekend tomorrow)StrategyNew pricing schemes get added as new classes, with zero changes to ParkingLot (OCP)

5Implementation

Vehicles & spot compatibility

python
from enum import Enum

class VehicleType(Enum):
    MOTORCYCLE = "motorcycle"
    CAR = "car"
    TRUCK = "truck"

class Vehicle:
    def __init__(self, license_plate: str, vehicle_type: VehicleType):
        self.license_plate = license_plate
        self.vehicle_type = vehicle_type

class SpotType(Enum):
    MOTORCYCLE = "motorcycle"
    COMPACT = "compact"
    LARGE = "large"

# which spot sizes each vehicle type is allowed to use
COMPATIBLE_SPOTS = {
    VehicleType.MOTORCYCLE: {SpotType.MOTORCYCLE, SpotType.COMPACT, SpotType.LARGE},
    VehicleType.CAR: {SpotType.COMPACT, SpotType.LARGE},
    VehicleType.TRUCK: {SpotType.LARGE},
}

Spots & floors

python
class ParkingSpot:
    def __init__(self, spot_id: str, spot_type: SpotType):
        self.spot_id = spot_id
        self.spot_type = spot_type
        self.vehicle: Vehicle | None = None

    def is_free(self) -> bool:
        return self.vehicle is None

    def park(self, vehicle: Vehicle):
        self.vehicle = vehicle

    def remove_vehicle(self):
        self.vehicle = None

class ParkingFloor:
    def __init__(self, floor_number: int, spots: list[ParkingSpot]):
        self.floor_number = floor_number
        self.spots = spots

    def find_available_spot(self, vehicle_type: VehicleType) -> ParkingSpot | None:
        compatible = COMPATIBLE_SPOTS[vehicle_type]
        for spot in self.spots:
            if spot.is_free() and spot.spot_type in compatible:
                return spot
        return None

Ticket & pricing strategy

python
from abc import ABC, abstractmethod
from datetime import datetime

class Ticket:
    def __init__(self, vehicle: Vehicle, spot: ParkingSpot):
        self.vehicle = vehicle
        self.spot = spot
        self.entry_time = datetime.now()
        self.exit_time: datetime | None = None

class PricingStrategy(ABC):
    @abstractmethod
    def calculate_fee(self, ticket: Ticket) -> float:
        pass

class HourlyPricingStrategy(PricingStrategy):
    RATES = {VehicleType.MOTORCYCLE: 10, VehicleType.CAR: 20, VehicleType.TRUCK: 30}

    def calculate_fee(self, ticket: Ticket) -> float:
        duration = ticket.exit_time - ticket.entry_time
        hours = max(1, duration.seconds // 3600 + 1)   # round up, minimum 1 hour
        return hours * self.RATES[ticket.vehicle.vehicle_type]

The ParkingLot itself (Singleton)

python
class ParkingLot:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, floors: list[ParkingFloor] = None, pricing_strategy: PricingStrategy = None):
        if getattr(self, "_initialized", False):
            return                                       # __init__ re-runs on every ParkingLot() call
        self.floors = floors or []
        self.pricing_strategy = pricing_strategy or HourlyPricingStrategy()
        self.active_tickets: dict[str, Ticket] = {}       # license_plate -> Ticket
        self._initialized = True

    def park_vehicle(self, vehicle: Vehicle) -> Ticket:
        for floor in self.floors:
            spot = floor.find_available_spot(vehicle.vehicle_type)
            if spot:
                spot.park(vehicle)
                ticket = Ticket(vehicle, spot)
                self.active_tickets[vehicle.license_plate] = ticket
                print(f"Parked {vehicle.license_plate} -> floor {floor.floor_number}, spot {spot.spot_id}")
                return ticket
        raise Exception(f"Parking lot full for vehicle type {vehicle.vehicle_type}")

    def unpark_vehicle(self, license_plate: str) -> float:
        ticket = self.active_tickets.pop(license_plate)
        ticket.exit_time = datetime.now()
        ticket.spot.remove_vehicle()
        fee = self.pricing_strategy.calculate_fee(ticket)
        print(f"{license_plate} exited. Fee: ${fee}")
        return fee

Putting it together

python
floor1_spots = (
    [ParkingSpot(f"1-M{i}", SpotType.MOTORCYCLE) for i in range(2)]
    + [ParkingSpot(f"1-C{i}", SpotType.COMPACT) for i in range(3)]
    + [ParkingSpot("1-L0", SpotType.LARGE)]
)
floor1 = ParkingFloor(1, floor1_spots)

lot = ParkingLot(floors=[floor1])

car = Vehicle("KA-01-1234", VehicleType.CAR)
ticket = lot.park_vehicle(car)          # Parked KA-01-1234 -> floor 1, spot 1-C0

fee = lot.unpark_vehicle("KA-01-1234")  # KA-01-1234 exited. Fee: $20

same_lot = ParkingLot()                 # Singleton -> same instance, same floors/state
print(lot is same_lot)                  # True

6. Extending the Design (common follow-ups)

🎤 "How would you support real-time spot availability displays at each entrance?"

Observer pattern — make ParkingFloor a subject that notifies registered DisplayBoard observers whenever a spot's occupied state flips, instead of having displays poll for state.

🎤 "How would you support multiple entry/exit gates running concurrently?"

The naive Singleton above is not thread-safe — two gates could both find the same "free" spot in the gap between checking is_free() and calling park(). Add a lock (either one global lock around park_vehicle, or a per-spot lock for less contention) so the check-and-reserve happens atomically.

🎤 "How would you add support for reserved/handicapped spots or membership pricing?"

Extend SpotType and add a new PricingStrategy implementation (e.g. MembershipPricingStrategy) — because pricing is already behind an interface, this is a pure extension with zero changes to ParkingLot, exactly per OCP.

🎤 "How would you handle payment failures at exit?"

Don't call remove_vehicle()/release the spot until payment succeeds. Model payment as its own step — a PaymentProcessor interface (Strategy/Adapter to a real gateway) called between fee calculation and spot release, so a failed charge leaves the vehicle "still parked" for a retry.

📌 Quick Revision — Cheat Sheet

  • Entities: Vehicle, ParkingSpot, ParkingFloor, ParkingLot, Ticket, PricingStrategy — six classes, six single responsibilities.
  • Singleton: exactly one ParkingLot — implemented via __new__, guarded re-init with _initialized.
  • Strategy: pricing is swappable/extensible without touching ParkingLot.
  • Composition: Lot → Floors → Spots, each level owning the one below it.
  • Compatibility map (COMPATIBLE_SPOTS) decouples "which vehicle fits which spot" from the matching logic itself — add a new vehicle/spot type by editing one dict, not the search algorithm.
  • Classic follow-ups to rehearse: concurrency/locking, real-time displays (Observer), new pricing schemes (Strategy/OCP), payment failure handling.
