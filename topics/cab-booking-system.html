Cab Booking System

An Uber/Ola-style ride matching service — where "which driver do we assign?" and "what do we charge?" are both just swappable strategies.

🚕 Practice Problem ⏱ ~22 min read 🎯 Two independent Strategies

1Problem Statement

Design a ride-booking system that supports:

  • Registering drivers with a live location and availability status.
  • A rider requesting a ride from a pickup to a drop location.
  • Matching the request to a suitable available driver.
  • Calculating a fare once the trip completes.

2Clarifying Requirements

FunctionalNon-functional
Match a rider to the "best" available driverMatching algorithm should be swappable (nearest-driver today, ETA-based later)
Track trip lifecycle: requested → accepted → completedFare calculation should be swappable (distance-based today, surge pricing later)
Calculate fare based on distanceA driver can only be matched to one active trip at a time

3Identifying Core Entities

EntityResponsibility
LocationA coordinate, with a distance calculation to another location
DriverLocation + availability status
RiderThe person requesting a ride
TripPickup/drop, matched driver, status, final fare
MatchingStrategyPicks a driver for a ride request
FareStrategyComputes the fare for a completed trip
RideBookingServiceThe single entry point coordinating drivers, matching, and fares

4Design Decisions & Patterns Used

DecisionPatternWhy
Driver selection logic is a separate, injectable objectStrategySwapping "nearest driver" for a smarter ETA/traffic-aware algorithm never touches RideBookingService

5Implementation

Locations, drivers, riders

python
from enum import Enum
from abc import ABC, abstractmethod
import math

class DriverStatus(Enum):
    AVAILABLE = "available"
    ON_TRIP = "on_trip"

class TripStatus(Enum):
    REQUESTED = "requested"
    ACCEPTED = "accepted"
    COMPLETED = "completed"
    CANCELLED = "cancelled"

class Location:
    def __init__(self, lat: float, lng: float):
        self.lat, self.lng = lat, lng

    def distance_to(self, other: "Location") -> float:
        return math.dist((self.lat, self.lng), (other.lat, other.lng))

class Driver:
    def __init__(self, driver_id: str, location: Location):
        self.driver_id = driver_id
        self.location = location
        self.status = DriverStatus.AVAILABLE

class Rider:
    def __init__(self, rider_id: str):
        self.rider_id = rider_id

class Trip:
    def __init__(self, trip_id: str, rider: Rider, pickup: Location, drop: Location):
        self.trip_id = trip_id
        self.rider = rider
        self.driver: Driver | None = None
        self.pickup = pickup
        self.drop = drop
        self.status = TripStatus.REQUESTED
        self.fare = 0.0

Matching & fare strategies

python
class MatchingStrategy(ABC):
    @abstractmethod
    def find_driver(self, drivers: list[Driver], pickup: Location) -> Driver | None:
        pass

class NearestDriverStrategy(MatchingStrategy):
    def find_driver(self, drivers, pickup):
        available = [d for d in drivers if d.status == DriverStatus.AVAILABLE]
        if not available:
            return None
        return min(available, key=lambda d: d.location.distance_to(pickup))

class FareStrategy(ABC):
    @abstractmethod
    def calculate(self, pickup: Location, drop: Location) -> float:
        pass

class DistanceFareStrategy(FareStrategy):
    RATE_PER_KM = 12
    BASE_FARE = 30

    def calculate(self, pickup, drop):
        return round(self.BASE_FARE + pickup.distance_to(drop) * self.RATE_PER_KM, 2)

RideBookingService (Singleton)

python
class RideBookingService:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self):
        if getattr(self, "_initialized", False):
            return
        self.drivers: list[Driver] = []
        self.trips: dict[str, Trip] = {}
        self.matching_strategy: MatchingStrategy = NearestDriverStrategy()
        self.fare_strategy: FareStrategy = DistanceFareStrategy()
        self._initialized = True

    def register_driver(self, driver: Driver):
        self.drivers.append(driver)

    def request_ride(self, rider: Rider, pickup: Location, drop: Location) -> Trip:
        driver = self.matching_strategy.find_driver(self.drivers, pickup)
        if not driver:
            raise Exception("No drivers available")

        trip = Trip(f"T{len(self.trips) + 1}", rider, pickup, drop)
        trip.driver = driver
        trip.status = TripStatus.ACCEPTED
        driver.status = DriverStatus.ON_TRIP
        self.trips[trip.trip_id] = trip
        print(f"Trip {trip.trip_id}: matched driver {driver.driver_id}")
        return trip

    def complete_trip(self, trip: Trip):
        trip.status = TripStatus.COMPLETED
        trip.fare = self.fare_strategy.calculate(trip.pickup, trip.drop)
        trip.driver.status = DriverStatus.AVAILABLE
        print(f"Trip {trip.trip_id} completed. Fare: {trip.fare}")

Putting it together

python
service = RideBookingService()
service.register_driver(Driver("D1", Location(12.90, 77.60)))
service.register_driver(Driver("D2", Location(12.95, 77.62)))

rider = Rider("R1")
trip = service.request_ride(rider, pickup=Location(12.91, 77.61), drop=Location(12.93, 77.64))
# Trip T1: matched driver D1

service.complete_trip(trip)
# Trip T1 completed. Fare: 32.87 (base fare + distance-based rate)

6. Extending the Design (common follow-ups)

🎤 "How would you add surge pricing during high demand?"

A new SurgeFareStrategy wrapping DistanceFareStrategy and multiplying by a demand factor — or, even better, a Decorator around any FareStrategy (SurgeDecorator(base_strategy, multiplier)), so surge pricing can stack on top of whichever base strategy is active without duplicating fare logic.

🎤 "How would riders see the driver's live location during the trip?"

Observer — the rider's app subscribes to a Trip's location updates; the driver's app periodically pushes location changes that notify all subscribed observers, without Trip needing to know how each client displays it.

🎤 "What if the driver cancels after accepting?"

This is where Trip's simple status enum starts to strain — a full State pattern (as in the Elevator and BookMyShow pages) becomes worthwhile once you have enough transition-specific rules (e.g. "cancellation after ACCEPTED triggers re-matching; cancellation after COMPLETED is invalid").

📌 Quick Revision — Cheat Sheet

  • Entities: Location, Driver, Rider, Trip, MatchingStrategy, FareStrategy, RideBookingService.
  • Two independent Strategies: who gets matched, and what it costs — neither depends on the other.
  • Singleton: one RideBookingService per city/region.
  • Surge pricing = Decorator around FareStrategy; live tracking = Observer; cancellation rules = a good trigger to upgrade to full State.
