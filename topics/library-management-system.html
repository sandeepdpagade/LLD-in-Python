Library Management System

The classic domain from the UML page, taken all the way to a runnable design — and the modeling insight that trips people up most: a book title is not a book copy.

📚 Practice Problem ⏱ ~20 min read 🎯 Catalog vs physical item modeling

1Problem Statement

Design a library system that supports:

  • A catalog of books, where each title may have multiple physical copies.
  • Members borrowing an available copy and returning it later.
  • Calculating a late fee if a copy is returned after its due date.

2Identifying Core Entities

EntityResponsibility
BookCatalog metadata: title, author, ISBN — not a physical, borrowable object
BookCopyOne physical copy of a Book, with its own borrow status
MemberA library user, tracking what they currently have borrowed
LoanOne borrow record: which copy, which member, issue/due/return dates
FineStrategyCalculates the late fee for a completed loan
LibraryThe single entry point — catalog, active loans, borrow/return operations
🚨 The modeling insight this problem is testing

A library owning 3 physical copies of "Clean Code" is one Book and three BookCopy objects — not three separate Books. Get this wrong and your design can't answer basic questions like "how many copies of this title are currently available?" without a mess of duplicate/inconsistent metadata.

3Design Decisions & Patterns Used

DecisionPatternWhy
Catalog metadata (Book) is separate from a borrowable unit (BookCopy)—Matches reality exactly: metadata is shared, availability is per-copy
Late fee calculation is a separate, injectable objectStrategySwitching from a flat daily rate to a tiered rate is a new class, not a rewrite of return_book
One Library instance owns the whole catalog and active loansSingletonA single source of truth for what's currently borrowed (per branch — see follow-ups)

4Implementation

Catalog: Book vs BookCopy

python
from enum import Enum
from datetime import datetime, timedelta
from abc import ABC, abstractmethod

class CopyStatus(Enum):
    AVAILABLE = "available"
    BORROWED = "borrowed"

class Book:                              # catalog metadata — one per title
    def __init__(self, isbn: str, title: str, author: str):
        self.isbn = isbn
        self.title = title
        self.author = author

class BookCopy:                          # one physical copy — many per Book
    def __init__(self, copy_id: str, book: Book):
        self.copy_id = copy_id
        self.book = book
        self.status = CopyStatus.AVAILABLE

class Member:
    def __init__(self, member_id: str, name: str):
        self.member_id = member_id
        self.name = name
        self.borrowed_copies: list[BookCopy] = []

Loan & fine strategy

python
class Loan:
    LOAN_PERIOD_DAYS = 14

    def __init__(self, copy: BookCopy, member: Member):
        self.copy = copy
        self.member = member
        self.issue_date = datetime.now()
        self.due_date = self.issue_date + timedelta(days=self.LOAN_PERIOD_DAYS)
        self.return_date = None

class FineStrategy(ABC):
    @abstractmethod
    def calculate(self, loan: Loan) -> float:
        pass

class DailyFineStrategy(FineStrategy):
    RATE_PER_DAY = 5

    def calculate(self, loan):
        if not loan.return_date or loan.return_date <= loan.due_date:
            return 0.0
        late_days = (loan.return_date - loan.due_date).days
        return late_days * self.RATE_PER_DAY

Library (Singleton)

python
class Library:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self):
        if getattr(self, "_initialized", False):
            return
        self.copies: list[BookCopy] = []
        self.loans: dict[str, Loan] = {}          # copy_id -> active Loan
        self.fine_strategy: FineStrategy = DailyFineStrategy()
        self._initialized = True

    def add_copy(self, copy: BookCopy):
        self.copies.append(copy)

    def find_available_copy(self, isbn: str) -> BookCopy | None:
        for copy in self.copies:
            if copy.book.isbn == isbn and copy.status == CopyStatus.AVAILABLE:
                return copy
        return None

    def borrow_book(self, isbn: str, member: Member) -> Loan:
        copy = self.find_available_copy(isbn)
        if not copy:
            raise Exception("No available copy for this book")
        copy.status = CopyStatus.BORROWED
        loan = Loan(copy, member)
        self.loans[copy.copy_id] = loan
        member.borrowed_copies.append(copy)
        print(f"{member.name} borrowed '{copy.book.title}', due {loan.due_date.date()}")
        return loan

    def return_book(self, copy: BookCopy) -> float:
        loan = self.loans.pop(copy.copy_id)
        loan.return_date = datetime.now()
        copy.status = CopyStatus.AVAILABLE
        loan.member.borrowed_copies.remove(copy)
        fine = self.fine_strategy.calculate(loan)
        print(f"Returned '{copy.book.title}'. Fine: {fine}")
        return fine

Putting it together

python
book = Book("978-0132350884", "Clean Code", "Robert C. Martin")
library = Library()
library.add_copy(BookCopy("C1", book))
library.add_copy(BookCopy("C2", book))     # a second physical copy, same Book

alice = Member("M1", "Alice")
loan = library.borrow_book(book.isbn, alice)     # Alice borrowed 'Clean Code', due ...

fine = library.return_book(loan.copy)             # Returned 'Clean Code'. Fine: 0.0

5. Extending the Design (common follow-ups)

🎤 "What happens when all copies of a book are borrowed?"

Add a reservation queue per Book. When a copy is returned, check for waiting members and notify the first one — a natural fit for the Observer pattern (the Book or Library notifies waiting members instead of them polling).

🎤 "How would you support multiple library branches?"

This is exactly why Library being a Singleton is a design choice tied to the requirement, not a universal rule — with multiple branches, each branch gets its own Library instance (no longer a Singleton), and a higher-level LibrarySystem could route requests to the correct branch or search across all of them.

🎤 "How would you search by author or genre efficiently?"

Don't linear-scan self.copies for this — maintain secondary indexes (e.g. dict[author, list[Book]]) updated whenever a book is added to the catalog, or delegate to a dedicated SearchService if the catalog grows large enough to warrant it (SRP: cataloging vs. searching are different concerns).

📌 Quick Revision — Cheat Sheet

  • Entities: Book, BookCopy, Member, Loan, FineStrategy, Library.
  • Key modeling insight: Book (catalog metadata) ≠ BookCopy (physical, borrowable unit).
  • Strategy: fine calculation is swappable without touching borrow/return logic.
  • Multi-branch support is the natural signal that Singleton was a requirement-specific choice, not a universal default.
