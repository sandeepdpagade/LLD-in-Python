Tic-Tac-Toe

A deceptively simple warm-up problem — the real test is whether your design generalizes past a 3x3 grid.

⭕ Practice Problem ⏱ ~15 min read 🎯 Strategy for pluggable win rules

1Problem Statement

Design a 2-player Tic-Tac-Toe game that:

  • Supports an N x N board, not just the fixed 3x3.
  • Validates moves (can't play an occupied cell, can't play out of turn).
  • Detects a win (row, column, or diagonal) or a draw after every move.

2Identifying Core Entities

EntityResponsibility
SymbolEnum: X, O, or empty
PlayerA name paired with a symbol
BoardOwns the grid; knows how to place a mark and check "is full"
WinningStrategyDecides whether a given symbol has won on the current board
TicTacToeGameOrchestrates turns and asks the strategy for a winner after each move

3Design Decisions & Patterns Used

DecisionPatternWhy
Win-checking logic lives outside Board and GameStrategySwapping "3-in-a-row anywhere on NxN" for "exactly 3-in-a-row on a 5x5 board" is a new class, not a rewrite
Board only knows about grid state, never about turns or win conditionsSRPThe board can be unit-tested (placement, fullness) completely independently of game rules

4Implementation

python
from enum import Enum
from abc import ABC, abstractmethod

class Symbol(Enum):
    X = "X"
    O = "O"
    EMPTY = "-"

class Player:
    def __init__(self, name: str, symbol: Symbol):
        self.name = name
        self.symbol = symbol

class Board:
    def __init__(self, size: int = 3):
        self.size = size
        self.grid = [[Symbol.EMPTY for _ in range(size)] for _ in range(size)]

    def place(self, row: int, col: int, symbol: Symbol) -> bool:
        if self.grid[row][col] != Symbol.EMPTY:
            return False
        self.grid[row][col] = symbol
        return True

    def is_full(self) -> bool:
        return all(cell != Symbol.EMPTY for row in self.grid for cell in row)

    def print_board(self):
        for row in self.grid:
            print(" ".join(cell.value for cell in row))
python
class WinningStrategy(ABC):
    @abstractmethod
    def check_winner(self, board: Board, symbol: Symbol) -> bool:
        pass

class RowColDiagonalStrategy(WinningStrategy):
    def check_winner(self, board, symbol):
        n, g = board.size, board.grid
        for i in range(n):
            if all(g[i][j] == symbol for j in range(n)):       # row i
                return True
            if all(g[j][i] == symbol for j in range(n)):       # column i
                return True
        if all(g[i][i] == symbol for i in range(n)):           # main diagonal
            return True
        if all(g[i][n - 1 - i] == symbol for i in range(n)):   # anti-diagonal
            return True
        return False

class TicTacToeGame:
    def __init__(self, players: list[Player], board_size: int = 3, strategy: WinningStrategy = None):
        self.players = players
        self.board = Board(board_size)
        self.strategy = strategy or RowColDiagonalStrategy()
        self.current_index = 0

    def play_turn(self, row: int, col: int) -> str:
        player = self.players[self.current_index]
        if not self.board.place(row, col, player.symbol):
            return "Invalid move, try again"
        if self.strategy.check_winner(self.board, player.symbol):
            return f"{player.name} wins!"
        if self.board.is_full():
            return "It's a draw!"
        self.current_index = (self.current_index + 1) % len(self.players)
        return "Next turn"

game = TicTacToeGame([Player("Alice", Symbol.X), Player("Bob", Symbol.O)])
print(game.play_turn(0, 0))   # Next turn
print(game.play_turn(1, 1))   # Next turn (Bob)
print(game.play_turn(0, 1))   # Next turn (Alice)
print(game.play_turn(2, 2))   # Next turn (Bob)
print(game.play_turn(0, 2))   # Alice wins! (top row: X X X)

5. Extending the Design (common follow-ups)

🎤 "How would you support 'K in a row' on an NxN board, not just a full row/column?"

Write a new KInARowStrategy(WinningStrategy) that scans in all four directions from the just-played cell (not the whole board) counting consecutive matching symbols — this is also an efficiency upgrade, since checking only from the last move is O(N) instead of re-scanning the entire board every turn.

🎤 "How would you add an AI opponent?"

Model Player as an interface with a get_move(board) method; a HumanPlayer reads input, an AIPlayer runs Minimax (with alpha-beta pruning for larger boards). TicTacToeGame doesn't need to know or care which kind of player it's dealing with — another natural Strategy split.

🎤 "How would you support undo?"

Command pattern — wrap each move as a PlaceMoveCommand with execute()/undo(), and have TicTacToeGame keep a history stack, exactly like the Command example on the Behavioral Patterns page.

📌 Quick Revision — Cheat Sheet

  • Entities: Symbol, Player, Board, WinningStrategy, TicTacToeGame.
  • Strategy: win-checking is fully decoupled — the tell-tale sign an interviewer is looking for.
  • Checking only from the last-played cell (not the whole board) is the efficiency answer for "K in a row" on large boards.
  • AI opponent and undo are the two most common extensions — both map to patterns you already know (Strategy, Command).
