Vending Machine

The canonical State-pattern interview question, taken all the way to a full working design with inventory and change.

🥤 Practice Problem ⏱ ~20 min read 🎯 State pattern, fully worked
💡 Why this is the textbook State example

You met a stripped-down version of this on the Behavioral Patterns page. Here it's taken to its natural conclusion: inventory, real coin values, change calculation, and a third state (Dispensing) — enough depth for an actual 45-minute interview round.

1Problem Statement

Design a vending machine that supports:

  • Inserting coins of different denominations.
  • Selecting a product by its slot code.
  • Dispensing the product and returning change, only once enough money has been inserted.
  • Refusing to dispense out-of-stock or insufficiently-paid-for items.

2Identifying Core Entities

EntityResponsibility
CoinEnum of accepted denominations and their values
ProductName and price
InventoryMaps slot codes to a product and remaining quantity
VendingStateDefines behavior for insert/select/dispense in one specific mode
VendingMachineHolds the current state, balance, and inventory; delegates every action to its state

3Design Decisions & Patterns Used

DecisionPatternWhy
Behavior for insert/select/dispense differs completely by modeStateNo mode ever needs an if machine.mode == "..." check — each state class only implements what's valid for it
Stock tracking lives entirely in Inventory, not in the statesSRPRestocking logic never risks touching state-transition logic

4Implementation

Coins, products, inventory

python
from enum import Enum
from abc import ABC, abstractmethod

class Coin(Enum):
    NICKEL = 5
    DIME = 10
    QUARTER = 25

class Product:
    def __init__(self, name: str, price: int):
        self.name = name
        self.price = price

class Inventory:
    def __init__(self):
        self.slots: dict[str, list] = {}     # slot_code -> [Product, quantity]

    def add_stock(self, slot_code: str, product: Product, quantity: int):
        self.slots[slot_code] = [product, quantity]

    def get_product(self, slot_code: str) -> Product:
        return self.slots[slot_code][0]

    def is_available(self, slot_code: str) -> bool:
        return slot_code in self.slots and self.slots[slot_code][1] > 0

    def reduce_stock(self, slot_code: str):
        self.slots[slot_code][1] -= 1

The three states

python
class VendingState(ABC):
    @abstractmethod
    def insert_coin(self, machine, coin: Coin): pass
    @abstractmethod
    def select_product(self, machine, slot_code: str): pass
    @abstractmethod
    def dispense(self, machine): pass

class IdleState(VendingState):
    def insert_coin(self, machine, coin):
        machine.balance += coin.value
        machine.state = machine.has_money_state
        print(f"Inserted {coin.name}, balance = {machine.balance}")

    def select_product(self, machine, slot_code):
        print("Insert coins first")

    def dispense(self, machine):
        print("Insert coins and select a product first")

class HasMoneyState(VendingState):
    def insert_coin(self, machine, coin):
        machine.balance += coin.value
        print(f"Inserted {coin.name}, balance = {machine.balance}")

    def select_product(self, machine, slot_code):
        if not machine.inventory.is_available(slot_code):
            print("Out of stock")
            return
        product = machine.inventory.get_product(slot_code)
        if machine.balance < product.price:
            print(f"Insufficient balance, need {product.price - machine.balance} more")
            return
        machine.selected_slot = slot_code
        machine.state = machine.dispensing_state
        machine.dispense()

    def dispense(self, machine):
        print("Select a product first")

class DispensingState(VendingState):
    def insert_coin(self, machine, coin):
        print("Please wait, dispensing in progress")

    def select_product(self, machine, slot_code):
        print("Please wait, dispensing in progress")

    def dispense(self, machine):
        product = machine.inventory.get_product(machine.selected_slot)
        machine.inventory.reduce_stock(machine.selected_slot)
        change = machine.balance - product.price
        print(f"Dispensing {product.name}. Change returned: {change}")
        machine.balance = 0
        machine.state = machine.idle_state

VendingMachine — the context

python
class VendingMachine:
    def __init__(self, inventory: Inventory):
        self.inventory = inventory
        self.balance = 0
        self.selected_slot = None
        self.idle_state = IdleState()
        self.has_money_state = HasMoneyState()
        self.dispensing_state = DispensingState()
        self.state: VendingState = self.idle_state    # start state

    def insert_coin(self, coin: Coin): self.state.insert_coin(self, coin)
    def select_product(self, slot_code: str): self.state.select_product(self, slot_code)
    def dispense(self): self.state.dispense(self)

inventory = Inventory()
inventory.add_stock("A1", Product("Coke", 35), quantity=5)

vm = VendingMachine(inventory)
vm.select_product("A1")        # Insert coins first
vm.insert_coin(Coin.QUARTER)   # Inserted QUARTER, balance = 25
vm.insert_coin(Coin.DIME)      # Inserted DIME, balance = 35
vm.select_product("A1")        # Dispensing Coke. Change returned: 0

5. Extending the Design (common follow-ups)

🎤 "How would you add a refund/cancel button?"

Add a cancel(machine) method to VendingState: in HasMoneyState it returns the full balance and transitions back to IdleState; in IdleState and DispensingState it's a no-op (nothing to refund, or too late to cancel).

🎤 "How would you support card payments alongside coins?"

Introduce a PaymentMethod interface (Strategy/Adapter) with CoinPayment and CardPayment implementations. HasMoneyState would work against the interface's "amount received" rather than coin-specific logic, so both payment types drive the same state machine.

🎤 "Why isn't VendingMachine itself a Singleton, unlike ParkingLot?"

Because a real building can have many independent physical vending machines, each with its own inventory and balance — there's no single global instance to protect, unlike a parking lot's one shared physical structure. Singleton is a fit only when the real-world entity is genuinely unique; always check that before reaching for it.

📌 Quick Revision — Cheat Sheet

  • Entities: Coin, Product, Inventory, VendingState, VendingMachine.
  • States: Idle → HasMoney → Dispensing → back to Idle, each with its own valid actions only.
  • Inventory (stock) is a separate concern from state (mode) — don't conflate the two.
  • Not every "system" needs a Singleton — ask whether the real-world thing is actually unique first.
